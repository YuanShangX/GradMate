第一部分：功能完善与角色定义
为了让系统构成一个完整的闭环（有数据来源，有数据消费），我们需要将系统分为**“小程序端（学生用）”和“Web管理端（管理员用）”**。
1. 角色定义
考研学生 (User): 使用微信小程序，获取资讯、查询院校、制定计划、使用AI助手。
系统管理员 (Admin): 使用Web后台（Vue3），维护院校数据、发布资讯、管理用户、查看统计数据。
2. 完善后的功能模块 (Refined Modules)
在原有基础上，增加了后台管理部分，并细化了AI和推荐逻辑：
A. 小程序端 (学生前端)
首页与资讯 (Info Hub): 搜索、Banner轮播（重要公告）、资讯分类Tab（政策/简章/经验）、个性化推荐流。
院校库 (University/Major): 院校筛选（地区/985/211）、专业目录查询、历年分数线图表展示（Echarts）、院校详情页。
学习伴侣 (Study Mate): 倒计时组件、每日任务清单（CRUD）、打卡日历、动态激励动画（点击互动）。
AI 智囊 (AI Helper): 调用大模型API（如DeepSeek/文心一言），提供“考研百科问答”、“长难句分析”、“择校建议”。
个人中心 (My Profile): 微信一键登录、目标院校/专业设定（核心数据，用于推荐）、收藏夹、浏览历史。

B. Web管理端 (管理员后台)
数据中心: 爬虫数据导入或手动录入（院校信息、分数线）。
资讯管理: 文章发布、编辑、删除、置顶。
用户管理: 查看注册用户列表、禁用违规用户。
AI配置: 配置API Key，查看AI调用日志（可选）。
第二部分：需求分析 (Requirement Analysis)
1. 业务需求 (Business Requirements)
核心目标: 解决考研信息不对称和碎片化问题，通过“目标锚定”算法，将原本需要用户主动搜的信息，通过规则自动推送到用户面前。
价值主张: 节省检索时间，提供情感陪伴（学习打卡与AI交互）。
2. 用户需求 (User Requirements)
即时性: 也是报名、现场确认等关键时间点，系统能主动提醒。
精准性: 我考“计算机”，别给我推“汉语言文学”的调剂信息。
便捷性: 不需要下载App，微信即开即用。
3. 功能需求 (Functional Requirements)
数据展示: 支持富文本解析（展示招生简章），支持图表渲染（分数线趋势）。
交互逻辑: 用户填写“目标院校”后，系统首页内容需动态刷新为相关内容。
AI响应: 响应时间需在3秒内，支持流式输出（打字机效果）。

第三部分：领域与范围分析
1. 问题领域 (Problem Domain)
垂直领域: 高等教育 -> 研究生入学考试。
关键实体: 考生、院校、专业、政策文件、考试科目。
2. 项目范围 (Scope)
做: 资讯聚合、院校数据查询、基础学习计划管理、AI文本辅助。
不做: 在线视频课程播放（流量成本高）、真题在线刷题系统（题库版权风险大）、复杂的社交论坛（审核风险大）。
第四部分：技术可行性分析
前端 (WeChat Mini Program): 微信开发者工具原生开发或使用Uni-app，覆盖面广，适合毕设演示。
后端 (Spring Boot + SpringMVC): 标准Java生态，稳定性高，易于集成MyBatis Plus操作数据库。
数据库 (MySQL): 关系型数据库，完美存储结构化的院校和用户信息。
管理端 (Vue3 + Element Plus): 现代化的SPA单页应用，开发效率高。
AI集成: 通过 HTTP Client (OkHttp/RestTemplate) 调用第三方大模型接口，技术门槛低，效果好。
